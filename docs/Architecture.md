# Архитектура PlantUML Studio

## Решения

macOS 14+, Swift, SwiftUI. Редактор — AppKit NSTextView вместо WKWebView/CodeMirror: системные поиск и замена, сочетания клавиш, отсутствие npm и внешнего редактора. Нумерация строк реализована NSRulerView. Предпросмотр — WKWebView, SVG от официального PlantUML. Поддерживаемые свойства редактируются через структурный список, без координатного редактора.

Модули Swift Package:

- PlantUMLCore: исходник, UTF-16 source ranges, разбор, диагностика, точечные изменения, безопасные операции и согласование идентификаторов.
- SequenceModule: типизированные участники, сообщения, типы участников, стрелки и блоки.
- ERModule: типизированные сущности, атрибуты, связи и кардинальности.
- Rendering: официальный Java-движок, ограничение процессов и памяти, таймаут и кэш.
- PlantUMLStudio: ApplicationDelegate, Workspace, StudioDocument, Editor, Preview, DocumentView и Constructor. Работа с файлами отделена от парсера и рендера.

SequenceModule и ERModule зависят только от Core. Rendering не зависит от UI или парсера. Общий лексический слой хранит неизвестные конструкции; расширение типов диаграмм не требует изменения редактора, файлового формата или рендера.

## Синхронизация

Исходник — единственный сохраняемый документ. Парсер не сериализует документ обратно. Изменение поля заменяет его диапазон; алиас меняется только в распознанных ссылках. При подозрении на ссылку в неизвестной конструкции операция отклоняется. Переименование алиаса выполняется отдельной операцией.

Source ranges используют UTF-16, как NSString и NSTextView. Изменения проверяются на границы и пересечения, применяются справа налево. CRLF сохраняется. Диапазон блока вычисляется парсером, а не поиском слова `end`, поэтому текст note не влияет на вложенность. Перемещение не пересекает ветви, закрывающие конструкции, комментарии или неизвестный код. При изменении текста идентификаторы согласуются по неизменённому префиксу/суффиксу и виду элемента; выбранный элемент сбрасывается, чтобы исключить применение старого диапазона.

После ввода: разбор, debounce 350 мс, фоновый рендер. Модель и SVG становятся актуальными после успешного рендера. Ошибки сохраняют последнюю корректную модель; операции заблокированы. Ответ старой версии документа игнорируется.

После визуальной операции: вычисление точечных изменений → структурная проверка → официальный рендер → применение, только если исходник за время проверки не изменился. Исходник не изменяется при отказе проверки. И ввод, и визуальные операции входят в общий UndoManager.

## Рендеринг и поставка

PlantUML 1.2025.0 запускается отдельным процессом Java 21.0.6+7. `-Playout=smetana` выбирает встроенный официальный движок раскладки без Graphviz и изменения исходника. Не более двух Java-процессов; до 256 МБ heap на процесс, таймаут 15 секунд. Файловые потоки предотвращают взаимную блокировку pipe при больших SVG. Кэш SHA-256 ограничен 12 результатами/32 МБ.

Runtime копируется в Resources приложения. Системная Java не нужна. При запуске через Swift Package используются зависимости в рабочей папке. Подпись ad hoc предназначена для локальной сборки. Intel Runtime и публичная notarization не входят в этот артефакт.

PlantUML работает в SECURE profile. В предпросмотре CSP блокирует внешние ресурсы; навигация по ссылкам SVG запрещена. Изолированный пользовательский скрипт отвечает за выбор текста и перемещение области просмотра.

## Файлы и состояние

UTF-8 `.puml`/`.plantuml`, атомарное сохранение Data. Отдельного проектного формата нет. Вкладки хранят независимые документы. При закрытии вкладки, окна или выходе запрашивается сохранение изменённых документов. Исходники и пути вкладок восстанавливаются через UserDefaults. Это восстановление сеанса при штатном завершении, а не журнал восстановления после сбоя.
