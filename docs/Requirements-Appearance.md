# Техническое задание: редизайн PlantUML Studio и поддержка тем оформления

## 1. Цель

Обновить визуальный стиль PlantUML Studio, используя цветовую палитру нового логотипа приложения.

Создать современный, минималистичный интерфейс, соответствующий принципам дизайна macOS, с полноценной поддержкой светлой, тёмной и системной тем.

**Основные требования:**
- Единый визуальный стиль приложения.
- Цветовая палитра на основе нового логотипа.
- Возможность ручного переключения темы.
- Автоматическое следование системной теме macOS.
- Сохранение выбранной темы между запусками.
- Нативный внешний вид и удобство повседневной работы.

## 2. Цветовая палитра

Использовать следующие цвета в качестве основы дизайн-системы.

| Назначение | Цвет | HEX |
|---|---|---|
| Основной тёмный | Deep Navy | `#172332` |
| Тёмно-зелёный | Forest Green | `#086B50` |
| Основной акцент | Emerald | `#20C997` |
| Дополнительный акцент | Mint | `#73E5BB` |
| Светлый фон | Soft White | `#F7F9F8` |
| Фон панелей | Light Gray | `#E9EFED` |
| Вторичный текст | Slate Gray | `#82929D` |

Допускается корректировка оттенков для обеспечения читаемости и контрастности.

Цвета должны использоваться через централизованные дизайн-токены, а не через отдельные константы в каждом компоненте.

## 3. Общий визуальный стиль

Приложение должно выглядеть как профессиональный нативный инструмент для macOS.

Требования:

- Минималистичный интерфейс без визуальной перегруженности.
- Графитовые, тёмно-зелёные и нейтральные поверхности.
- Изумрудные и мятные акценты.
- Аккуратные скругления элементов.
- Тонкие разделители между панелями.
- Компактные элементы управления.
- Нативная типографика SF Pro и SF Mono.
- Единая система отступов и размеров.
- Ненавязчивые анимации.
- Использование стандартных паттернов macOS.

Избегать:

- Чрезмерных градиентов.
- Неонового свечения.
- Избыточных теней.
- Декоративных элементов без функциональной ценности.
- Чрезмерного использования Liquid Glass.
- Интерфейса, визуально напоминающего веб-приложение.

Приоритет отдавать удобству работы с кодом и диаграммами.

## 4. Темы оформления

Реализовать три режима оформления.

### 4.1. System

Тема автоматически определяется настройками macOS.

При изменении системного оформления приложение должно переключаться между светлой и тёмной темами без перезапуска.

### 4.2. Light

Светлая тема используется независимо от системных настроек.

Характеристики:

- Светлый нейтральный фон.
- Белые или светло-серые панели.
- Тёмный текст.
- Изумрудные акценты.
- Мягкое выделение активных элементов.
- Минимальное количество декоративных эффектов.

### 4.3. Dark

Тёмная тема используется независимо от системных настроек.

Характеристики:

- Глубокий графитово-синий фон.
- Немного более светлые поверхности панелей.
- Светлый основной текст.
- Мятно-зелёные и изумрудные акценты.
- Сдержанная подсветка выбранных элементов.
- Высокая читаемость редактора кода.

Тёмная тема должна визуально соответствовать основной палитре логотипа PlantUML Studio.

## 5. Настройки оформления

Добавить раздел **Settings → Appearance**.

Разместить в нём переключатель:

- System
- Light
- Dark

Требования:

1. Тема применяется сразу после выбора.
2. Перезапуск приложения не требуется.
3. Выбор сохраняется между запусками.
4. По умолчанию используется System.
5. Переключение распространяется на все окна приложения.
6. При выборе System приложение реагирует на изменения оформления macOS.
7. Выбранная тема не должна сбрасываться после обновления приложения.

Для хранения предпочтения использовать стандартные механизмы macOS, например `UserDefaults` или `@AppStorage`.

## 6. Редактор PlantUML

Редактор кода должен использовать оформление, соответствующее выбранной теме.

Требования:

- Отдельные цветовые схемы подсветки синтаксиса для Light и Dark.
- Контрастное отображение ключевых слов.
- Различимые цвета комментариев, участников, сообщений и конструкций.
- Подсветка активной строки.
- Подсветка ошибок.
- Подсветка выделенного текста.
- Корректное оформление номеров строк.
- Согласованные цвета курсора и выделения.

Не использовать исключительно зелёные оттенки для всей подсветки синтаксиса.

При переключении темы сохранять:

- Положение курсора.
- Выделенный текст.
- Положение прокрутки.
- Историю Undo/Redo.
- Несохранённые изменения.

## 7. Конструктор и диаграммы

Обновить оформление:

- Sequence Constructor.
- ER Constructor.
- Component Constructor, если он уже реализован.
- Outline.
- Properties Panel.
- Command Palette.
- Панели поиска.
- Вкладок документов.
- Инструментов масштабирования.
- Контекстных меню.

Активные элементы выделять мягким изумрудным или мятным акцентом.

Не использовать чрезмерно яркие заливки.

**Важно:** переключение темы интерфейса не должно автоматически менять цвета и стили пользовательских PlantUML-диаграмм.

Диаграммы должны сохранять оформление, заданное в исходном `.puml`.

## 8. Анимации и взаимодействия

Использовать короткие, ненавязчивые анимации для:

- Переключения панелей.
- Открытия меню.
- Изменения состояния кнопок.
- Выбора элементов.
- Переключения режимов просмотра.

Анимации не должны замедлять работу приложения.

Учитывать системную настройку Reduce Motion.

При переключении темы не должно происходить заметного мерцания интерфейса или повторной загрузки документов.

## 9. Техническая реализация

### 9.1. Дизайн-система

Создать централизованную систему дизайн-токенов.

Предусмотреть семантические значения:

- Background.
- Surface.
- Elevated Surface.
- Primary Text.
- Secondary Text.
- Accent.
- Selection.
- Border.
- Error.
- Warning.
- Success.

Для каждого токена определить значения в светлой и тёмной темах.

### 9.2. Управление темой

Реализовать единый механизм управления оформлением.

Он должен:

- Хранить выбранный пользователем режим.
- Определять фактически используемую тему.
- Передавать состояние всем компонентам.
- Реагировать на системные изменения.
- Обновлять встроенный редактор кода, включая компоненты внутри WKWebView.
- Исключать рассинхронизацию оформления между окнами.

### 9.3. Совместимость

Необходимо сохранить:

- Существующую архитектуру.
- Функциональность редактора.
- Работу конструктора.
- Двустороннюю синхронизацию PlantUML.
- Историю изменений.
- Открытие и сохранение файлов.
- Производительность.

Не изменять парсер, генератор PlantUML и бизнес-логику ради визуального оформления.

## 10. Тестирование

Проверить:

1. Переключение System → Light → Dark.
2. Сохранение темы после перезапуска.
3. Автоматическую смену темы при изменении настроек macOS.
4. Корректное отображение всех основных экранов.
5. Согласованность оформления SwiftUI/AppKit и WKWebView.
6. Читаемость подсветки синтаксиса.
7. Отсутствие потери несохранённых изменений.
8. Сохранение состояния редактора при смене темы.
9. Корректную работу нескольких окон.
10. Отсутствие изменений пользовательских PlantUML-диаграмм.

Проверить контрастность основных текстовых и интерактивных элементов по WCAG AA там, где применимо.

## 11. Критерии приёмки

Задача считается завершённой, если:

- Весь интерфейс PlantUML Studio приведён к единому визуальному стилю.
- Используется палитра нового логотипа.
- Реализованы светлая, тёмная и системная темы.
- Тема переключается без перезапуска.
- Выбор пользователя сохраняется.
- Все панели и редактор корректно реагируют на смену темы.
- Светлая и тёмная темы одинаково удобны для работы.
- Нет элементов со старым несогласованным оформлением.
- Не нарушена существующая функциональность.
- Пройдены необходимые тесты.

**Итоговая цель:** PlantUML Studio должна выглядеть как современная нативная IDE для macOS с узнаваемой графитово-изумрудной палитрой, аккуратным интерфейсом и полноценным управлением темами оформления.
