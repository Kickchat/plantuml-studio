# Технический план

## Источники и среда

Приложен только текст ТЗ. Пользователь разрешил использовать официальную документацию plantuml.com вместо отсутствующего гайда. Исходная рабочая папка была пустой. Доступны Swift 6.4, Xcode 27.0, Apple Silicon; системной Java и Graphviz нет.

## Этапы

1. Зафиксировать грамматику поддерживаемых Sequence и IE-конструкций и ограничения в SupportMatrix.md. Не реализовывать собственную геометрию диаграмм.
2. Подготовить Swift Package, Xcode build target, SwiftUI окно, NSTextView редактор, WKWebView SVG preview, независимые вкладки, файловые операции.
3. Реализовать исходник как основной документ; диапазоны UTF-16, структурный стек вложенности, неизвестный синтаксис без сериализации, согласование идентификаторов и точечные операции.
4. Добавить типизированные SequenceModule / ERModule и конструктор: свойства, создание, удаление, безопасный порядок, проверка результата PlantUML перед изменением исходника.
5. Поставить фиксированный официальный PlantUML и Java внутри .app. Выбрать Smetana для автономной ER-раскладки; ограничить память, время и конкуренцию процессов.
6. Проверить unit, round-trip, integration, corpus fixtures, Xcode сборку и запуск реального приложения. Подготовить инструкции и ограничения.

## Проверки приёмки

Исходный текст без изменений сохраняется идентично. Визуальное изменение меняет только необходимые диапазоны. Алиасы обновляют распознанные ссылки и не угадывают неизвестные. Перестановка не пересекает структурные границы. Ошибка не изменяет исходник, сохраняет последнее корректное состояние и блокирует конструктор. SVG/PNG создаются официальным локальным движком. Undo/Redo проверяются в процессе приложения.

Полный перечень реализованного синтаксиса и ограничений — SupportMatrix.md и KnownLimitations.md. Эти документы важнее общего названия MVP при оценке поддерживаемых альтернативных форм.
